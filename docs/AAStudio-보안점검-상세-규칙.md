# AAStudio 보안점검 상세 규칙

## 1. 목적

이 문서는 AAStudio가 코드 흐름 기준으로 보안 위험 후보를 어떤 항목으로 점검할지 정의한다.

AAStudio는 전용 보안 솔루션을 대체하지 않는다. 대신 소스 코드와 호출 흐름을 읽고 리뷰 보조용 후보 이슈를 정리한다.

## 2. 기본 원칙

- 상세 취약점 진단은 전용 솔루션이 담당한다.
- AAStudio는 코드 기준 후보 분석과 리뷰 보조를 담당한다.
- 파일/라인 근거를 함께 남긴다.
- 확정 판정이 아니라 검토 대상 분류를 우선한다.

## 3. 점검 항목

### 3.1 입력/쿼리 계열

- 코드 인젝션
- SQL 인젝션
- 불필요한 method 악용

### 3.2 출력/렌더링 계열

- XSS
- 에러 페이지 미적용
- 정보 누출

### 3.3 경로/파일 계열

- 디렉토리 인덱싱
- 악성 파일 업로드
- 파일 다운로드 취약점

### 3.4 인증/권한 계열

- 약한 비밀번호 정책
- 불충분한 인증 절차
- 불충분한 권한 검증
- 취약한 비밀번호 복구 절차
- 관리자 페이지 노출

### 3.5 세션/쿠키 계열

- 불충분한 세션 관리
- 쿠키 변조

### 3.6 네트워크/전송 계열

- SSRF
- 데이터 평문 전송

### 3.7 프로세스/검증 계열

- 프로세스 검증 누락
- 자동화 공격

## 4. 분석 방식

### 4.1 코드 흐름 기반

- 입력값이 어디서 들어오는지 본다.
- 검증이 어디서 수행되는지 본다.
- 출력이 어디로 나가는지 본다.
- 권한 체크가 어디에 있는지 본다.

### 4.2 후보 이슈 생성

- 위험 가능성이 보이면 후보 이슈를 만든다.
- 각 이슈에 근거 파일과 라인을 연결한다.
- 심각도와 신뢰도를 함께 표시한다.

### 4.3 분리 원칙

- AAStudio 결과는 후보 이슈다.
- 전용 솔루션 결과는 상세 취약점이다.
- 두 결과는 함께 보여주되 분리해서 관리한다.

## 5. 출력 예시 항목

- 파일 경로
- 라인 범위
- 점검 항목
- 위험도
- 근거 설명
- 수정 권고
- 상태
