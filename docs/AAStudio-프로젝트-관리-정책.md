# AAStudio 프로젝트 관리 정책

## 1. 목적

AAStudio는 하나의 프로그램 안에서 여러 프로젝트를 생성하고 전환하며 관리할 수 있어야 한다.

## 2. 기본 원칙

- 프로그램은 다중 프로젝트를 지원한다.
- 각 프로젝트는 서로 분리된 작업 공간을 가진다.
- 프로젝트별로 소스, 문서, 산출물, 첨부파일, 이력을 독립 관리한다.
- 한 프로젝트의 변경이 다른 프로젝트에 영향을 주지 않도록 한다.

## 3. 프로젝트 단위

각 프로젝트는 다음을 포함한다.

- 소스 폴더
- 분석 결과
- 소스코드 점검 결과
- 보안점검 결과
- DB 모델
- 다이어그램
- API 명세
- Wiki
- WBS
- 첨부파일
- 접근 로그
- 프로젝트 대시보드

## 4. 프로그램 수준 기능

- 프로젝트 생성
- 프로젝트 열기
- 프로젝트 전환
- 프로젝트 복사
- 프로젝트 내보내기
- 프로젝트 가져오기
- 프로젝트 삭제
- 최근 프로젝트 목록
- 프로젝트 검색

## 5. 프로젝트 분리 규칙

- 프로젝트별 SQLite 데이터는 분리하거나 프로젝트 ID로 명확히 구분한다.
- 첨부파일 경로도 프로젝트 기준으로 분리한다.
- readonly 공유도 프로젝트 단위로 제어한다.
- 내보내기와 가져오기는 프로젝트 전체 또는 일부 산출물 단위로 지원한다.

## 6. UI 반영

- 좌측 상단에 프로젝트 전환 영역을 둔다.
- 최근 프로젝트 목록을 제공한다.
- 현재 열려 있는 프로젝트가 항상 보이게 한다.
- 프로젝트별 대시보드에서 개발 단계별 담당자 정보를 표시한다.

## 7. 프로젝트 대시보드 표시 정보

프로젝트별 대시보드는 개발 단계마다 다음 정보를 표시할 수 있어야 한다.

- 담당자명
- 직급
- 담당자 연락처
- 담당자 이메일
- 관련 업무 또는 산출물
- 현재 단계 상태

## 8. 단계별 관리 예시

- 기획
- 분석
- 설계
- 구현
- 검토
- 배포 준비
- 완료

## 9. 다음 단계

이 정책을 기준으로 요약 설계서와 SQLite 테이블 초안의 프로젝트 구조를 확장한다.
