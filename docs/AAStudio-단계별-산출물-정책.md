# AAStudio 단계별 산출물 정책

## 1. 목적

AAStudio는 각 분석 단계마다 중간 결과만 남기는 것이 아니라, 해당 단계의 최종 산출물을 생성해야 한다.

이 문서는 단계별로 어떤 산출물을 만들고, 어떤 형식으로 저장할지 정의한다.

## 2. 기본 원칙

- 각 단계는 끝날 때 반드시 최종 산출물을 남긴다.
- 산출물은 사람이 바로 읽을 수 있어야 한다.
- 산출물은 재생성 가능해야 한다.
- 산출물은 Wiki, 파일, JSON, 문서 중 적절한 형태로 저장한다.

## 3. 단계별 산출물

### 3.1 소스 스캔 단계

- 최종 산출물: 소스 스캔 요약
- 내용:
  - 스캔 범위
  - 파일 목록
  - 언어/프레임워크 추정
  - 주요 엔트리포인트
- 저장 형태:
  - JSON
  - Markdown 요약

### 3.2 소스코드 점검 단계

- 최종 산출물: 소스코드 점검 리포트
- 내용:
  - 규칙 위반 후보
  - 유지보수 이슈
  - 코드 스멜
  - 리뷰 포인트
- 저장 형태:
  - Markdown 리포트
  - JSON 이슈 목록

### 3.3 보안점검 단계

- 최종 산출물: 보안점검 후보 리포트
- 내용:
  - 점검 항목별 후보 이슈
  - 파일/라인 근거
  - 위험도
  - 권고 조치
- 저장 형태:
  - Markdown 리포트
  - JSON 이슈 목록

### 3.4 DB 모델링 단계

- 최종 산출물: DB 모델 설계서
- 내용:
  - 테이블
  - 컬럼
  - 관계
  - 제약조건
  - DDL 초안
- 저장 형태:
  - Markdown
  - JSON
  - SQL 초안

### 3.5 다이어그램 단계

- 최종 산출물: ERD 산출물
- 내용:
  - 노드
  - 관계선
  - 레이아웃
  - 렌더링 결과
- 저장 형태:
  - PNG/SVG/PDF
  - JSON 레이아웃 데이터

### 3.6 API 명세 단계

- 최종 산출물: API 명세서
- 내용:
  - endpoint
  - request/response schema
  - status code
  - auth 여부
  - 예제 payload
- 저장 형태:
  - OpenAPI JSON/YAML
  - Markdown 문서

### 3.7 Wiki 단계

- 최종 산출물: Wiki 페이지 본문과 버전 이력
- 내용:
  - 설명 본문
  - 근거 파일
  - 관련 산출물 링크
  - 버전 기록
- 저장 형태:
  - Markdown 또는 rich text
  - version snapshot

### 3.8 WBS 단계

- 최종 산출물: WBS 구조 문서
- 내용:
  - 업무 계층
  - 연결 산출물
  - 상태
  - 우선순위
- 저장 형태:
  - JSON
  - Markdown 요약

## 4. 산출물 생성 규칙

- 각 단계 완료 시 자동으로 저장한다.
- 사용자가 검토 후 확정할 수 있어야 한다.
- 확정 전 산출물은 `draft`로 표시할 수 있다.
- 확정 후 산출물은 `final`로 표시한다.

## 5. 화면 반영

- 각 탭에 `최종 산출물 생성` 버튼을 둔다.
- 생성된 산출물은 미리보기와 저장 경로를 함께 보여준다.
- readonly 모드에서는 생성 버튼이 비활성화된다.

## 6. 다음 단계

이 정책을 적용하면 AAStudio는 단계별 분석 도구가 아니라 단계별 산출물 생성 도구가 된다.
