# AAStudio 분석 흐름도

## 1. 목적

AAStudio가 로컬 PC에서 소스를 읽고, 점검하고, 구조화하고, 문서화하고, 공유하기까지의 전체 흐름을 정의한다.

## 2. 흐름 요약

1. 프로젝트를 연다.
2. 프로젝트를 선택하거나 전환한다.
3. 소스 폴더를 지정한다.
4. 소스 스캔을 수행한다.
5. 소스코드 점검을 수행한다.
6. 표준단어사전 점검을 수행한다.
7. 보안점검 항목을 코드 흐름 기준으로 검토한다.
8. DB 모델링 초안을 만든다.
9. 다이어그램 초안을 만든다.
10. API 명세를 소스코드 기준으로 동기화한다.
11. 필요 시 API를 수동으로 추가한다.
12. 실제 백엔드 호출 테스트를 수행한다.
13. 공통 인증을 적용한다.
14. 샘플 데이터가 DB에 유지되는지 확인한다.
15. Wiki와 WBS로 정리한다.
16. 파일을 첨부하고 버전을 남긴다.
17. 필요 시 readonly로 공개한다.
18. 각 단계별 최종 산출물을 생성한다.

## 3. 세부 흐름

### 3.1 입력 단계

- 프로젝트 선택
- 소스 경로 선택
- 분석 범위 선택
- 공유 모드 선택

### 3.2 스캔 단계

- 파일 수집
- 언어와 프레임워크 추정
- 엔티티/DTO/라우트 후보 추출
- 규칙 기반 점검 기준 적용

### 3.3 소스코드 점검 단계

- PMD, SonarQube류 정책 기준으로 코드 구조를 확인
- 코드 스멜과 유지보수 이슈 후보를 추출
- 위험한 패턴과 리뷰 포인트를 표시

### 3.4 표준단어사전 점검 단계

- 소스코드에서 VO 후보 추출
- 표준단어사전 로드
- VO와 단어사전 비교
- 미등록 단어 추출
- 권장 표기와 수정 후보 제안
- 점검 리포트 생성
- 점검결과 엑셀 생성

### 3.5 보안점검 단계

- 코드 흐름 기준으로 취약점 후보를 추정
- 상세 진단은 전용 솔루션과 분리
- AAStudio는 후보 이슈와 근거를 정리

### 3.6 구조화 단계

- 테이블 후보 생성
- 관계 후보 생성
- API endpoint 후보 생성
- API 동기화 비교
- 문서화용 초안 생성

### 3.7 API 동기화/수동관리 단계

- 소스코드에서 API를 자동 추출
- 수동으로 API 추가
- 자동/수동 항목 비교
- 변경 이력 기록

### 3.8 API 테스트 단계

- 실제 백엔드 서버로 호출
- 공통 인증 정보 적용
- 샘플 데이터 기반 요청 구성
- 응답과 문서 비교
- 테스트 결과 저장

### 3.9 정리 단계

- Wiki에 설명 추가
- WBS에 업무 항목 연결
- 첨부파일 저장
- 버전 이력 생성

### 3.10 공유 단계

- readonly 공개 여부 확인
- 문서와 다이어그램 열람 허용
- 파일 다운로드 허용
- 수정과 업로드는 차단

### 3.11 산출물 생성 단계

- 소스 스캔 요약 생성
- 소스코드 점검 리포트 생성
- 표준단어사전 점검 리포트 생성
- 표준단어사전 점검 엑셀 생성
- 보안점검 후보 리포트 생성
- DB 모델 설계서 생성
- ERD 산출물 생성
- API 명세서 생성
- API 테스트 리포트 생성
- API 동기화 리포트 생성
- Wiki 버전 문서 생성
- WBS 구조 문서 생성
