# AAStudio 화면 구성

## 1. 목적

AAStudio의 사용자 화면을 어떤 정보 구조로 배치할지 정의한다.

핵심은 소스 분석, 소스코드 점검, 보안점검, DB 모델링, 다이어그램, API 명세, Wiki, WBS, 파일 관리를 한 화면 체계 안에서 자연스럽게 오가게 만드는 것이다.
이 문서는 기능 목록이 아니라 실제 화면 설계 기준을 정리하는 문서다.

## 2. 화면 원칙

- 로그인 화면과 업무 화면을 분리한다.
- 로그인 후에는 공통 상단 내비게이션을 유지한다.
- 좌측은 탐색, 중앙은 작업, 우측은 상세 속성으로 고정한다.
- 상단은 전역 동작, 중앙은 기능 작업, 우측은 선택 항목 속성으로 역할을 분리한다.
- 자동 생성 결과와 수동 편집을 분리하고, 같은 항목 안에서 충돌하지 않게 배치한다.
- 로컬 전용과 readonly 공유를 같은 구조에서 다루되, 권한에 따라 조작 가능 여부만 달라지게 한다.
- 핵심 화면은 프로젝트 대시보드, 프로젝트 관리, 사용자 관리, 코드 그룹 관리, 소스 점검, 보안점검, DB 모델링, API 명세, Wiki, WBS 순으로 노출한다.
- 현재 구현 화면은 단일 데이터소스를 기준으로 동작한다.

## 5. 반응 흐름

- 소스 스캔 완료 시 점검 결과가 자동으로 탭에 반영된다.
- 사용자가 특정 항목을 선택하면 우측 패널에 상세가 열린다.
- Wiki 저장 시 버전 이력과 첨부 메타데이터가 같이 저장된다.
- readonly 공유 모드에서는 편집 버튼이 비활성화된다.
- 각 탭에는 `최종 산출물 생성` 동작이 있어야 한다.
- 프로젝트 대시보드는 각 단계의 담당자 정보를 요약해서 보여준다.
- 프로젝트 대시보드는 단계 상태와 이력도 함께 보여준다.
- 단계별 담당자 배정 화면에서 담당자 변경을 입력할 수 있다.
- API 테스트 화면에서 실행 결과와 히스토리를 함께 확인한다.
- 파일, Wiki, WBS는 모두 좌측 탐색에서 빠르게 이동 가능해야 한다.

## 6. 우선순위

1. 프로젝트 전환과 대시보드가 먼저 보여야 한다.
2. 소스 분석, 소스코드 점검, 보안점검 결과가 중앙 작업의 핵심이다.
3. DB 모델링, 다이어그램, API 명세는 생성과 검토 흐름을 지원한다.
4. Wiki, WBS, 파일 관리는 문서화와 연결을 담당한다.
5. API 테스트 화면은 명세 탭과 묶어서 연동한다.
