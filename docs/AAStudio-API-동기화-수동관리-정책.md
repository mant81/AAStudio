# AAStudio API 동기화 및 수동관리 정책

## 1. 목적

AAStudio의 API 명세는 실제 소스코드를 기준으로 자동 동기화할 수 있어야 하며, 동기화되지 않는 항목은 수동으로 추가할 수 있어야 한다.

## 2. 기본 원칙

- API 명세의 기본값은 소스코드 동기화다.
- 수동 추가는 보완 수단이다.
- 동기화와 수동 추가는 함께 사용할 수 있다.
- 변경 이력은 남겨야 한다.

## 3. 소스코드 동기화

- 라우터, 컨트롤러, 핸들러, DTO, Request/Response를 분석한다.
- 신규 API는 자동 추가한다.
- 변경된 path, method, schema는 자동 갱신한다.
- 삭제된 API는 비활성화 또는 삭제 후보로 표시한다.
- 인증/권한 정보도 함께 반영한다.

## 4. 수동 추가

- 코드에 없는 임시 API를 등록할 수 있다.
- 외부 연동용 API를 수동으로 추가할 수 있다.
- 문서용 예제 API를 수동으로 추가할 수 있다.
- 자동 동기화 결과와 수동 항목은 구분해서 저장한다.

## 5. 충돌 처리

- 자동 동기화와 수동 수정이 충돌할 수 있다.
- 충돌 시 마지막 수정자와 변경 이력을 확인할 수 있어야 한다.
- 필요 시 수동 우선 또는 자동 우선 정책을 프로젝트별로 둘 수 있다.

## 6. 운영 화면

- 소스코드 동기화 실행 버튼
- 수동 API 추가 버튼
- 변경 이력 확인 영역
- 동기화 결과 비교 영역

## 7. 다음 단계

이 정책은 API 명세 출력 형식과 API 테스트 화면에 연결된다.
